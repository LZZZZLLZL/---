# 13 · 代理复用规程（成本控制）

> 起因：第 1—10 章按「每章新开写手 + 每章新开评审」跑，10 章用了 17 个代理，成本明显过高。
> 本节定死复用规则，后续批次一律照此执行。

---

## 一、写手：一个代理写多章

**规则**：**一个写手代理承接同一幕内的连续多章**，只在该代理明显跑偏或该幕结束时才换人。

**为什么**：写手每接一个新章，都要重新读圣经、简报、细纲、上一章结尾——这部分成本（几千 token）每章都要付一次。复用之后，这些上下文已在它的会话里，新任务的简报可以只有「细纲那几行 + 本章边界」。

**怎么做**：用 `send_message` 给已有的写手代理派下一章，**不要**再 `subagent` 新开。任务描述里只需要写：

```
继续写下一章，还是你写。
只写第 N 章《标题》。
细纲：<细纲条目原文>
已定稿事实（对得上）：<只写本章要用到的那几条>
边界：<本章禁止出现的项>
硬要求：字数、标点、钩子原文、口癖、场景具体度
写入路径 → 只回复一行
```

## 二、评审：一个代理审多章

**规则**：**一个评审代理一次审 2—3 章**，按批复用；只有当某一章争议大或需要全新视角时才换人。

**为什么**：评审的价值在于「知道标准 + 知道全书已定稿事实」。这两样都是会话级的，复用一次就省一次。

**怎么做**：`send_message` 给已有评审代理，一次给 2—3 章，并明确要求「**重点核对上一轮指出的问题是否已整改**」——复核比首审便宜得多。

**判黄要收紧**：整改过多轮的章节，评审容易为小文字问题继续判黄，形成无限循环。复用时必须写明：**按放行标准判，不为小文字问题判黄**。

## 三、主代理自己做的事（不外派）

| 环节 | 为什么自己做 |
| --- | --- |
| 机械校验 | 一段脚本，一次跑完，外派反而慢 |
| 定稿与整改 | 跨章一致性只有拿全局的人判断得准；外派会出现「评审说改这句、改完又撞另一章」 |
| 归档（日志/伏笔表/边界/看板） | 是记账，不是创作，外派无收益 |
| 与用户确认口径 | 只有主代理该做 |

## 四、成本红线

- **每章 ≤ 1 次评审**（首审即放行，或有明确问题才复审一次）；
- **每批（5—10 章）新开代理数 ≤ 3 个**；
- 出现「同一章审到第三轮」就停下来，由主代理直接改到放行为止，不再派评审。

## 五、已经踩过的坑

| 坑 | 表现 | 现在怎么做 |
| --- | --- | --- |
| 草稿竞态 | 评审读到写手的中间版本，报告的结论与行号全废 | 写手一次 write 写完全文；评审报告首行必须写它读到的汉字数 |
| 主编挪动段落 | 第 4 章把结尾前移，造成「她离开两次、书包状态三次反复」 | 挪动后必须重读整章的动作链 |
| 跨章同构 | 第 9 章复刻第 3 章的办公室场景拍子；第 5、7 章都以环境清单开头 | 每章交稿后与前一章做一次「拍子对比」 |
| 钱/器物口径漂 | 枕头下的 800 被写成 1600；绿萝变仙人掌 | 跨章数字一律以 `06-连续日志.md` 的「钱的全流程」表与器物登记为准 |
