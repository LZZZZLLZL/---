# 《第一名有罪》写作工作流

**目标**：用可重复、可校验的流水线，把一本百万字级的校园长篇一章一章写出来，且不崩人设、不断伏笔。

**与上游预设的关系**：本工作流吸收了开源插件 `dsh-novel-solo`（Tkingxiao）随包预设 `novel-solo` 的审核规范——A–H 八维度、绿黄红三色判定、六维禁AI腔清单、强制前置检查、版本化写作，已合并进 `09-审核标准.md`。
本工作流在上游基础上多做三件事：**知识边界闸门**（防剧透，上游没有）、**伏笔表三列追踪**（防断线）、**批次闸门**（并行写作的衔接校验）。

**核心原则**：一章一循环。作者（写手）只负责"这一章"，评审只负责"挑毛病"，主编只负责"定稿与记录"。任何一步失败就地重跑，不回退整批。

---

## 一、目录结构

```
第一名有罪/
├── README.md                项目总览与入口（先读这个）
├── 01-圣经.md               设定圣经（人物/世界观/文风/命名规范）——极少改动，改动需评审
├── 02-总大纲.md             100 章章目 + 分卷结构
├── 03-细纲-ch001-030.md     细纲（当前写作用）
├── 04-知识边界.md           读者/角色此刻知道什么（防剧透、防崩）——永不删除
├── 05-伏笔表.md             埋下 / 现身 / 回收，三列强制追踪
├── 06-连续日志.md           每章状态快照（时间/地点/关系/钱/分数/物件）——永不删除
├── 07-进度看板.md           章目 × 状态 × 字数，含流程事故记录
├── 08-写作工作流.md         本文件
├── 09-审核标准.md           A–H + I/J 维度、三色判定、禁AI腔
├── 10-批次脚本.md           批量流水线调用模板
├── chapters/                ← 定稿正文（只增不改；大改另存 v(X+1)）
│   └── ch001.md
├── drafts/                  ← 写作草稿（可覆盖，草稿不是成果）
│   └── ch001.draft.md
└── reports/                 ← 审核报告（重审时新建版本，旧版删除）
    └── ch001.review.md
```

**分类铁律**：

| 目录 | 装什么 | 可否覆盖 | 可否删除 |
| --- | --- | --- | --- |
| 根目录编号文档 | 设定、大纲、细纲、边界、伏笔、日志、看板、流程、标准、脚本 | 可改（编号永不变） | `04-知识边界.md`、`06-连续日志.md` **永不删除**；细纲过期后可归档 |
| `chapters/` | 定稿正文 | **不可覆盖**，大改另存 v(X+1) | 不可删 |
| `drafts/` | 草稿 | 可覆盖 | 可删 |
| `reports/` | 审核报告 | 重审时新建版本 | 旧版报告可删；定稿对应报告保留至全书终审 |

**编号即引用**：文档之间一律用「编号-名」互指（如 `08-写作工作流.md`），**永远不要用"第几节""上面那个文件"来指代**。新增文档依次取号；插入文档用 `NN-a`，不重排既有编号。

采用 Markdown 而非数据库：人和模型都能直接读，git 可追溯，重跑无副作用。

## 二、四个角色

| 角色 | 职责 | 输入 | 输出 | 硬约束 |
| --- | --- | --- | --- | --- |
| **写手（Writer）** | 写本章正文 | 圣经 + 本章细纲 + 前一章定稿 + 知识边界 + 最近 3 条连续日志 | `drafts/chNNN.draft.md` | 只写本章；不允许提前使用"未来信息"；字数 2800—3500 |
| **评审（Reviewer）** | 挑毛病，不给答案 | 草稿 + 细纲 + 知识边界 + 伏笔表 | `reports/chNNN.review.md` | 必须给出可执行的修改点，不得重写全文 |
| **主编（Editor）** | 定稿 | 草稿 + 评审报告 | `chapters/chNNN.md` | 只改评审指出的问题；不得新增情节 |
| **档案员（Archivist）** | 维护状态 | 定稿 | 更新连续日志 / 伏笔表 / 进度看板 | 只记录事实，不做创作判断 |

> 角色隔离的意义：同一个人既写又审，会自我辩护。评审必须由**没有参与写作**的 agent 担任。

## 三、单章循环（每章一次）

```
        ┌──────────────────────────────────────────┐
        │                                          │
 ① 取任务 ──▶ ② 写手写草稿 ──▶ ③ 评审打分 ──▶ ④ 通过？──否──▶ ⑤ 写手返修 ──┘
                                              │
                                              是
                                              ▼
                                    ⑥ 主编定稿 ──▶ ⑦ 档案员归档 ──▶ 下一章
```

**② 写手简报（固定模板，逐字发给写手）**

```
你是《第一名有罪》的写手。只写第 N 章，不写别的。

【硬性要求】
- 字数 2800—3500 汉字
- 章末必须留钩子（用物件或一句话，不用感叹）
- 情绪落在动作与物件上，禁止直白心理独白
- 场景不超过 3 个，出场人物不超过 4 个
- 本章必须有一个"称重"：钱 / 分数 / 感情，三者至少一个被量化
- 只能使用【知识边界】里标注为"读者已知/角色已知"的信息，禁止提前使用后续章节的信息
- **标点**：对话与引语一律用中文弯引号 ""，禁止半角双引号；交稿前 `grep -c '"' 文件` 必须为 0
- **落盘纪律**：一次 write 写完，不分次追加；写完用 bash 统计汉字数并报告，数字必须与文件一致
- 不要写章节标题，不要写"第 N 章"字样，正文直接开始

【圣经】<粘贴 01-圣经.md 中"文风"与"人物卡·本章出场角色"两节>
【本章细纲】<粘贴 03-细纲 中第 N 章条目>
【前一章结尾】<粘贴 ch(N-1).md 最后 400 字>
【知识边界】<粘贴 04-知识边界.md 中"N 章时刻"`
【最近状态】<粘贴 06-连续日志.md 最后 3 条>

【输出】只输出正文 Markdown，不要任何解释、不要代码块围栏。
```

**③ 评审：按 `09-审核标准.md` 执行**

审核采用 **A–H 八维度 + 本项目 I、J 两维度 + 绿黄红三色判定**：

| 维度 | 内容 |
| --- | --- |
| A 设定一致 | 与圣经的世界观 / 规则 / 信物系统无矛盾 |
| B 人物性格一致 | 言行由性格底色驱动，与人物卡逐项比对 |
| C 大纲一致 | 关键情节点逐点核对，未落实判黄、整段缺失判红 |
| D 叙事质量 | 视角严格执行、文风节奏、忌直写心理标签 |
| E 正文规则 | 字数 2800—3500 / 章末钩子 / 承上启下 |
| F 禁AI腔 | 六维度判定，**先否定后转折即红** |
| G 剧情逻辑连贯 | **权重最高**——必须有新事件，前章钩子必须兑现 |
| H 物理与动作合理 | 动作衔接、身体位置与感官匹配 |
| **I 知识边界** | **致命项**，用了 ❌ 信息即整章重写 |
| **J 称重** | 钱 / 分数 / 感情至少一个被量化 |

**判定**：全绿放行；出现黄灯即不合格，整改后重审（**整改必须动情节结构，只做文字润色不予通过**）；红项打回重写。
本项目在 09 的三色之上补一条执行细节：返修最多 2 轮，2 轮不过由主编介入，简化情节或调整细纲。

**⑥ 主编定稿**：只按评审报告逐条修，禁止顺手美化。

**⑦ 档案员归档**：更新三处——
- `06-连续日志.md`：追加一条（时间 / 地点 / 人物状态 / 钱 / 分数 / 关系位移）
- `05-伏笔表.md`：新埋的伏笔登记，本章回收的标记
- `07-进度看板.md`：本章状态改为「定稿」+ 实际字数

## 四、批量模式（每批 7—10 章）

单章循环适合精修，但速度慢。批量模式用于赶进度：

```
批次 B（N 章）：
  for 每一章 i（严格串行）：
      写手写 ch_i → 评审 ch_i → 主编定稿 ch_i → 档案员归档 ch_i
  批末：阶段5 批次闸门：全批连续日志自检 + 伏笔表核对 + 时间线校验
```

> 修订说明：早期版本让同一批的章节并行起草，与"每章必须承接上一章章末钩子"的硬要求冲突（见第九节缺陷 #2）。现已改为**按章串行**。

**批次闸门（必做）**：抽 3 章做"跨章一致性检查"——时间是否连续、称呼是否变化、钱数是否算得通、分数是否前后矛盾。任一项失败，只返修问题章，不重跑整批。

## 五、章末自检卡（写手交稿前逐条打勾）

- [ ] 本章有没有一个"称重"？
- [ ] 结尾那句能不能让读者想翻下一页？
- [ ] 有没有用了不该用的信息？（对照知识边界）
- [ ] 出场人物的说话方式，遮住名字我能认出是谁吗？
- [ ] 有没有一句直白的心理独白可以直接改成动作？
- [ ] 字数在 2800—3500 之间吗？

## 六、防崩机制（长篇最要命的三件事）

**1. 人设漂移** → 人物卡里写死三样东西：**一个口头习惯、一个身体反应、一个绝对不做的事**。每 10 章做一次"人物卡比对"，抽 3 章检查这三个标记是否还在。

**2. 伏笔断线** → 伏笔表强制三列：埋于（章号）/ 现于（章号列表）/ 收于（章号或"待定"）。任何伏笔连续 20 章未出现，触发"提醒"；连续 40 章未出现，必须在下一批里让它露面一次。

**3. 时间线错乱** → 连续日志每条必须写清"距高考还有 X 天"（第 30 章后启用）。所有章节的时间锚点统一挂在这条线上。

## 七、给 agent 的调用规则

| 场景 | 用法 |
| --- | --- |
| 写 1 章 | 一个 subagent（写手）→ 一个 subagent（评审）→ 主编（主 agent 自己）定稿归档 |
| 写一批 7—10 章 | `workflow` 工具：写手阶段 fan-out，评审阶段 fan-out，定稿阶段串行 reduce |
| 长篇一致性审计 | `workflow` 工具：每 10 章一个 agent 做跨章检查，最后 reduce 成问题清单 |

**绝对不要在同一个 agent 里既写又审。** 这是这套工作流唯一不能省的规矩。

---

## 八、本工作流的已知代价

- **质量与速度不可兼得**：单章循环精修一章约 3 次 agent 调用；批量模式省一半，但会产生需要返修的衔接问题。
- **百万字需要约 40—50 个批次**，按每批 8 章算。这不是一次会话能完成的工程，必须分批推进。
- **评审不是万能的**：评审只能发现逻辑与人设问题，发现不了"无聊"。每 10 章建议由主 agent 亲自通读一次，判断节奏是否拖沓。

## 九、已修复的流程缺陷（持续追加）

| # | 缺陷 | 现象 | 修复 | 落在哪 |
| --- | --- | --- | --- | --- |
| 1 | **草稿竞态** | 评审读到写手的中间版本草稿（第 1 章：评审按 2577 字批"字数不足"，实际定稿前草稿已扩到 3092 字），评审行号与部分结论全部失效 | ①写手必须在**一次 write** 内写完并落盘；②交稿必须用 bash 自查汉字数并报告，数字与文件不符视为交稿无效；③评审报告第一行必须写明它读到的汉字数，与写手数字不符即中止并报"版本不一致" | `10-批次脚本.md` 二之二 |
| 2 | **批量写作顺序假设错误** | 原设计让同一批的 7 章草稿并行互不可见，"靠细纲+日志保证衔接"——但细纲规定每章必须承接上一章的章末钩子，并行时上一章还没写完 | 批量模式改为**按章串行**（写 N → 审 N → 写 N+1）；真要并行只能用于同一卷内**无前后钩子依赖**的独立支线章 | 本节 |
| 3 | **评审维度与上游预设不一致** | 早期用"6 项 12 分制"，与 `dsh-novel-solo` 预设的 A–H 八维度、三色判定不衔接 | 全量改用 A–H + 本项目 I（知识边界）、J（称重）共 10 维度、绿黄红三色判定 | `09-审核标准.md` |
| 4 | **文件职责混乱** | 草稿、定稿、评审报告最初全塞在 `chapters/` 里 | 拆成 `chapters/`（定稿）/ `drafts/`（草稿）/ `reports/`（报告）三个目录，并写明覆盖与删除规则 | 本节第一节 |

### 批量模式修订后的正确顺序

```
批次 B（N 章）：
  for 每一章 i（严格串行）：
      写手写 ch_i → 评审 ch_i → 主编定稿 ch_i → 档案员归档 ch_i
  批末：批次闸门（跨章一致性抽查 3 章）
```

**串行的代价**：慢。**并行的代价**：章末钩子接不上、人物状态打架，返修成本比省下的时间高得多。本项目选择串行，只在**同一卷内互无因果依赖的支线章**上放开并行。
