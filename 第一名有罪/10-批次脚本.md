# 08 · 批量流水线调用模板

> 本文件是"怎么真的把一章章跑出来"的操作手册。单章用手工三连（写手→评审→主编），
> 一批 7—10 章用 `workflow` 工具，脚本模板见下。

---

## 一、单章手工三连（精修用）

```
1. subagent（写手）  → 产出 drafts/chNNN.draft.md
2. subagent（评审）  → 产出 reports/chNNN.review.md   ← 必须是与写手无关的新 agent
3. 主编（主 agent）  → 按评审意见定稿 chapters/chNNN.md
4. 档案员            → 更新 06-连续日志 / 04-伏笔表 / 07-进度看板
```

**写手简报**：照抄 `08-写作工作流.md` 第三节的模板，替换章号。
**评审简报**：见本文件第四节。

---

## 二、批量脚本（workflow 工具）

把下列脚本作为 `workflow` 工具的 `script` 参数，`args` 传入本批章节清单。

```js
// args.chapters = [{ id: "ch001", title: "...", brief: "本章细纲全文" }, ...]
const ROOT = "/Users/wuqu/Project/You-Who-Sat-Beside-My-Desk/第一名有罪";

const briefFor = (c, prevTail) => `
你是《第一名有罪》的写手。只写 ${c.id}（${c.title}），不写别的。

【必读（先用 read 工具读完）】
${ROOT}/01-圣经.md
${ROOT}/03-细纲-ch001-030.md
${ROOT}/04-知识边界.md
${ROOT}/06-连续日志.md

【本章细纲】
${c.brief}

【前一章结尾】
${prevTail || "（本章为开篇，无前一章）"}

【硬性要求】
- 字数 2800—3500 汉字
- 不写章节标题，正文直接开始
- 不超过 3 个场景、4 个出场人物
- 章末必须留钩子（物件或一句话）
- 必须有一个「称重」（钱/分数/感情至少一个被量化）
- 情绪落在动作与物件上，禁止直白心理独白
- 只准使用 04-知识边界.md 中标 ✅ 的信息，用了 ❌ 的信息本章作废
- 标点：对话与引语一律用中文弯引号，禁止半角双引号；交稿前 grep -c '"' 必须为 0
- 落盘纪律：一次 write 写完，不分次追加；写完用 bash 统计汉字数并报告，数字必须与文件一致
- 短句、白描、克制。不用"仿佛/宛如/犹如"

【输出】把正文 Markdown 写入 ${ROOT}/drafts/${c.id}.draft.md
只回复一行：已写入 ${c.id}.draft.md，字数 XXXX 汉字。不要回复正文。
`;

phase("起草");
const drafts = await parallel(
  args.chapters.map((c) => () => agent(briefFor(c, c.prevTail), { label: `${c.id} 起草` }))
);

phase("评审");
const reviews = await parallel(
  args.chapters.map((c) => () =>
    agent(`
你是《第一名有罪》的评审，**你没有参与写作**。请审 ${c.id}。

读这四个文件：
${ROOT}/drafts/${c.id}.draft.md
${ROOT}/03-细纲-ch001-030.md（本章条目）
${ROOT}/04-知识边界.md
${ROOT}/09-审核标准.md

按 **A—H + I、J 共 10 个维度**逐项判定绿/黄/红（判定标准见 09-审核标准.md）：
A 设定一致 / B 人物性格一致 / C 大纲一致 / D 叙事质量 / E 正文规则
F 禁AI腔（六维度；先否定后转折即红）
G 剧情逻辑连贯（权重最高；必须有新事件，前章钩子必须兑现）
H 物理与动作合理
I 知识边界（**致命项**，用了 ❌ 信息即整章重写）
J 称重（钱/分数/感情至少一个被量化）

同时用 bash 统计汉字数，判断是否落在 2800—3500。

输出格式（一行一字段）：
章号：${c.id}
汉字数：XXXX
A 设定一致：绿|黄|红｜原因｜改法
B 人物性格一致：绿|黄|红｜原因｜改法
C 大纲一致：绿|黄|红｜原因｜改法
D 叙事质量：绿|黄|红｜原因｜改法
E 正文规则：绿|黄|红｜原因｜改法
F 禁AI腔：绿|黄|红｜原因｜改法
G 剧情逻辑连贯：绿|黄|红｜原因｜改法
H 物理与动作合理：绿|黄|红｜原因｜改法
I 知识边界：绿|红｜原因｜改法
J 称重：绿|黄|红｜原因｜改法
结论：全绿放行 / 修改后重审 / 打回重写

把报告写入 ${ROOT}/reports/${c.id}.review.md，然后只回复：${c.id} 独立结论 XX。
`, { label: `${c.id} 评审` })
  )
);

phase("汇总");
return args.chapters.map((c, i) => ({
  id: c.id,
  draft: drafts[i],
  review: reviews[i],
}));
```

**定稿阶段不放进脚本**：定稿必须串行（第 N 章定稿后才定第 N+1 章），由主 agent 逐章处理，避免衔接错位。

## 二之二、竞态协议（必读，本项目已踩过一次）

### 事故记录

第 1 章：评审子代理读到的是**中间版本草稿**（2577 字），写手随后又把草稿扩写到 3092 字才结束回合。评审报告针对的是过期内容，其"字数不足"的扣分与部分行号全部失效。

### 三条硬规矩

**1. 写手一次落盘，不做增量。**
草稿必须**在一次 write 里写完全文**。禁止"先写一半落盘、再补写"——中间态一旦落盘，评审就可能读到它。

**2. 写手交稿前必须自查并报告数字。**
用 bash 统计汉字数，确认落在 2800—3500，再回复。回复格式固定为一行：`已写入 chNNN.draft.md，字数 XXXX 汉字`。**报告的数字与文件实际数字不一致，视为交稿无效。**

**3. 评审必须在写手回合彻底结束后才开始。**
单章流程：写手 subagent 的回合结束通知到达后再派评审。
批量流程：`workflow` 脚本里 `parallel` 的写手阶段会等到全部 thunk 完成后才继续，**这是屏障，不要改成 pipeline 让写手与评审交错**。

### 评审自己的防呆

评审报告第一行必须写明**它读到的草稿汉字数**。若这个数字与写手的交稿数字不符，评审应中止并报告"草稿版本不一致"，而不是硬着头皮给出评审意见。

### 写手简报里必须加的一段话

```
【落盘纪律】
草稿必须在一次 write 里写完，不要分次追加。
写完用 bash 统计汉字数（python3 统计 \u4e00-\u9fff），确认在 2800—3500 之间。
你的回复只有一行：已写入 chNNN.draft.md，字数 XXXX 汉字。
报告的数字必须与文件实际一致。
```

## 三、批次闸门（批次跑完必做）

抽 3 章做跨章一致性检查，检查清单：

| 项 | 检查内容 |
| --- | --- |
| 时间 | 相邻章之间的时间推进是否连续，天数算得通吗 |
| 称呼 | 沈砚对周予晚的称呼是否变化（全书固定"周予晚"直到 99 章） |
| 钱 | 每章金额是否前后一致（任务 800/月、透析 400/次、一学期 4800） |
| 分数 | 名次是否矛盾（起始 46/47，第 20 章进前二十，第 32 章一模前二十，第 78 章前十） |
| 物件 | 信物状态是否连贯（铃铛不响、旧手机开不了机、便利贴被撕过） |

任一项失败：只返修问题章，不重跑整批。

## 四、评审简报模板（手工单章用）

```
你是《第一名有罪》的评审，**你没有参与写作**。请审第 N 章。

【读】drafts/chNNN.draft.md、03-细纲的本章条目、04-知识边界.md

【打分】6 项 × 0—2 分，共 12 分
1 细纲符合度  2 知识边界（致命项）  3 文风一致
4 人物一致    5 钩子              6 称重

【输出】
总分：X/12
致命项：通过 / 不通过
问题清单：<位置 + 具体改法，不许重写全文>
判定：通过（≥10 且致命项通过）/ 返修

写入 reports/chNNN.review.md，只回复一行结论。
```

## 五、每批结束后的自查（主 agent 亲自做）

- [ ] 通读本批所有定稿，判断节奏是否拖沓（评审发现不了"无聊"）
- [ ] 对照 `05-伏笔表.md`：本批该埋的埋了没有，该露面的露面了没有
- [ ] 更新 `07-进度看板.md` 与 `06-连续日志.md`
- [ ] 超过 20 章未露面的伏笔，排进下一批
